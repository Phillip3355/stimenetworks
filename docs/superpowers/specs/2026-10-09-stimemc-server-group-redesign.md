# StimeMC Server Group 리디자인 설계

작성일: 2026-10-09 (Asia/Seoul).

이 설계는 사용자의 전체 리디자인 요청, 2026-10-09 사전 조사, 승인받은 페이지 구성, 후속 Geyser 강조 요청을 기준으로 한다. 예전 Living Archive 설계에서 폐기된 기능은 현재 구현의 근거로 삼지 않는다.

## 1. 목적과 승인된 방향

StimeMC를 단일 게임 서버가 아니라 여러 Minecraft 서버를 운영하는 상위 브랜드로 표현한다. 브랜드 위계는 `STIMEMC → SERVER → SEASON / CONTENT`다.

첫 메시지는 `ONE COMMUNITY. MORE WORLDS.`와 `여러 세계, 하나의 Stime.`이다. 기술은 첫 메시지를 대신하지 않지만, **Geyser를 통한 Java × Bedrock 동시 접속은 모든 StimeMC 서버가 공유하는 가장 중요한 특징 중 하나로 강조한다.**

사용자는 짧은 브랜드 Hero 다음에 두 서버 패널이 펼쳐지는 모션 구간을 두는 구성을 승인했다. 모바일에서는 같은 메시지를 세로 흐름으로 전달하고 서버 안내를 빠르게 찾을 수 있게 한다.

## 2. 범위와 사실 처리

- 공개 화면에 등장하는 서버는 `THE GREAT WAR`와 `SURVIVAL`뿐이다.
- The Great War는 현재 개발 및 운영 준비 중인 전쟁 서버이며 한 시즌 운영할 계획이다. 실제 접속 가능 여부가 확인되기 전에는 `CURRENT / 운영 준비 중`으로 표현한다. `CURRENT`는 브랜드의 현재 서버라는 뜻이며 실시간 온라인 상태를 뜻하지 않는다.
- Survival은 별도로 추가할 Vanilla / Vanilla+ 중심 서버다. `PLANNED / COMING LATER`와 출시 버전·일정 미정 상태를 항상 표시한다.
- Survival의 클라이언트 모드 없는 플레이와 Geyser 크로스플레이는 StimeMC가 유지하는 운영 방향으로 설명한다. 아직 운영 중이라는 문장은 쓰지 않는다.
- 새 경제, 국가, 직업, RPG, 던전, 상점, 랭킹, 통계, 계정, Discord 연동, 지도, 서버 API는 추가하지 않는다.
- 현재 서버 상태 및 플레이어 수 API가 없으므로 숫자나 실시간 접속 상태를 표시하지 않는다.
- 공개 접속 주소·포트가 없으므로 입력값이나 Copy 버튼의 예시값을 만들어내지 않는다.
- 기존 1.21.1 안내는 기존에 공개된 접속 안내로 보존한다. 전쟁 서버의 확정 버전으로 전용하지 않는다.
- 오래된 게시물과 역사적 원문은 삭제·재작성하지 않는다. 과거 던전 서버의 콘텐츠는 새 서버의 기능으로 가져오지 않는다.

## 3. 정보 구조와 경로

| 경로 | 역할 |
| --- | --- |
| `/` | 브랜드, 서버 선택, 크로스플레이, 실제 기록, 최근 뉴스, 접속 안내 |
| `/servers` | 현재 서버와 계획 중 서버를 비교하는 서버 허브 |
| `/servers/the-great-war` | 현재 전쟁 서버의 확정된 소개와 준비 상태, 기존 안내로 연결 |
| `/servers/survival` | 추가할 야생 서버의 확정 방향과 계획 상태 |
| `/join` | 서버 상태 확인 → 에디션 선택 → 실제 공개된 접속 안내 |
| `/rules` | 기존 규칙 원문, 적용 범위 안내, 조회와 신고 |
| `/recovery-guidelines` | 기존 정책과 요청 절차, 서버별 정책 확장이 가능한 구조 |
| `/news` | 실제 보고서 목록 |
| `/updates` | 기존 홈페이지 업데이트 기록 |
| `/server-mechanism` | 확인된 Geyser / ViaProxy 접속 구조와 에디션별 제한 사항 |
| `/history` | 기존 StimeMC 운영 역사 |
| `/support` | 기존 회원·비회원 문의 흐름 |

`/taskboard`, `/auth/callback`, 기존 보고서 slug와 문의 알림 API도 유지한다. 특히 대문자 `/News`는 과거 보고서 URL이므로 `/news`로 정규화하지 않는다. 새 정적 경로는 보고서 catch-all보다 우선하도록 App Router의 일반 구조를 따른다.

Navigation은 `Servers / News / Guide / About / Join`으로 정리한다. Guide에는 규칙, 복구, 문의를, About에는 기술과 역사를 배치하고 업데이트 링크도 계속 제공한다. 관리자 진입은 현재 권한 흐름을 유지한다. 새 가입 신청·음성 기능은 만들지 않는다.

## 4. 시각 체계

전체는 짙은 남청색·청록색의 어두운 캔버스와 민트 포인트를 사용한다. 실제 Minecraft 풍경이 보이도록 이미지 위 오버레이를 절제한다.

| 역할 | 색상 |
| --- | --- |
| Canvas | `#071013` |
| Surface | `#0b191d` |
| Raised | `#10242a` |
| Primary text | `#edf5f2` |
| Secondary text | `#b3c7c4` |
| Muted text | `#91aaa7` |
| Brand accent | `#8fe2cc` |
| Blue accent | `#8cb9d1` |
| Hairline | `rgba(166,211,201,.20)` |
| War emphasis | `#d5b09a` |

색상은 서버 구분을 돕지만 상태는 반드시 텍스트로도 표현한다. 과도한 네온, 발광, Blur와 둥근 SaaS 카드를 피한다. 얇은 선, 직선, 0–6px 모서리, 큰 패널과 명료한 그리드를 사용한다.

영문 제목은 압축된 산세리프 스택, 한국어 본문은 기존 Pretendard / Noto Sans KR / 시스템 산세리프 스택을 사용한다. 새 외부 폰트 요청은 필수로 만들지 않는다. 모바일 본문은 최소 15px, line-height 1.7을 기준으로 한다. Hero는 영어 두 줄의 짧은 메시지로 유지하고 각 화면 구간의 크기를 별도로 정의한다.

`DESIGN.md`는 이 체계와 기기별 구성으로 갱신한다. `REDESIGN_NOTES.md`는 현재 존재하는 기능·데이터 계약을 기준으로 정리한다.

## 5. 홈의 서사

### Scene 01 — StimeMC

큰 StimeMC 워드마크, 짧은 핵심 문구, 한국어 한 문장과 `서버 살펴보기` CTA를 둔다. 브랜드 아래에 작은 `MINECRAFT SERVER GROUP` 라벨을 제공한다. 현재 접속 안내는 Header에서 항상 찾을 수 있다.

Hero는 단순한 배경 사진과 텍스트 중첩에 머물지 않는다. 이미지 창, 브랜드 레이어와 다음 장면의 패널이 연속된 구성을 이루게 한다. 첫 화면에서는 화면을 압도하는 게임 시스템 설명을 넣지 않는다.

### Scene 02 / 03 — More Worlds / Servers

하나의 StimeMC 프레임에서 두 서버 패널이 분리되는 짧은 장면을 만든다. 브랜드 이름은 두 패널의 공통 상위 영역에 남는다. 이후 패널은 실제 서버 정보와 상세 링크로 이어진다.

- The Great War: 현재 서버, 운영 준비 상태, 전쟁 중심의 확정된 설명, `서버 알아보기`.
- Survival: 계획 상태, 별도로 추가할 야생, Vanilla / Vanilla+ 방향, `계획 살펴보기`.

전쟁 서버의 실제 이미지 출처가 확인되지 않았으므로 패널에는 타입·선·절제된 색조로 성격을 표현한다. Survival도 실제 맵을 연상시키는 가짜 이미지 대신 그래픽과 타이포를 사용한다.

### Scene 04 / 05 — 두 서버의 방향

전쟁 서버는 현재 준비하는 한 시즌의 전쟁 중심 서버라는 공개 가능한 범위만 짧게 보여준다. 상세 페이지의 규칙, 접속 안내, 공지 링크로 이어진다.

Survival은 Minecraft 기본 야생 경험, 필요한 서버사이드 모드와 데이터팩, 별도 클라이언트 모드 없이 플레이하는 방향을 보여준다. 버전·날짜·모드 목록·맵을 확정하지 않는다.

### Scene 06 — Java × Bedrock / Geyser

이 섹션은 보조 설명 카드가 아니라 두 에디션이 함께 플레이한다는 특징을 보여주는 짧은 모션 장면이다.

- 제목: `JAVA × BEDROCK`.
- 카피: `기기가 달라도, 함께 플레이.`
- 설명: `StimeMC의 모든 서버는 Geyser를 통해 Java와 Bedrock 플레이어를 연결합니다.`
- Java와 Bedrock 레이블이 양쪽에서 같은 Geyser 브리지로 이어지고, 그 아래 StimeMC의 서버 선택지가 나타난다.
- 이 그림은 지원 에디션과 서버 그룹의 개념을 설명한다. 신규 라우팅 인프라나 단일 프록시 구성을 실제 구축한 것처럼 표현하지 않는다.
- 모바일에서는 두 입력을 나란히 두고 아래로 연결되는 짧은 세로 모션을 사용한다. 태블릿은 두 입력과 중앙 브리지를 함께 보여준다.
- Reduced motion에서는 전체 연결과 레이블을 즉시 표시한다.
- 모션은 섹션 진입 시 한 번만 실행하며 기술 페이지 링크를 항상 제공한다.

그룹의 모든 서버에 적용되는 특징임을 서버 허브와 각 서버 상세 페이지에도 짧은 공통 배지로 반복한다. Survival에는 계획 상태 배지를 함께 둔다.

### Scene 07 — StimeMC Archive

기존 실제 스크린샷을 이미지 갤러리로 보존한다. `STIMEMC ARCHIVE / 기존 서버 기록`임을 명확히 하고 새 전쟁 서버의 화면으로 표기하지 않는다. 원본은 그대로 보존하고 화면별 최적화는 `next/image`를 사용한다.

### Scene 08 / 09 — News / Join

Supabase의 실제 최근 게시물을 기존 서버 측 조회 함수로 가져온다. 원문에 서버 분류가 없으면 임의로 The Great War / Survival 태그를 부여하지 않고 StimeMC 소식으로 표시한다. 조회 실패나 빈 목록에는 실제 상태 안내를 제공한다.

마지막 CTA는 현재 서버 상세와 Join 가이드로 연결한다. 준비 중인 서버를 즉시 접속할 수 있다고 표현하지 않는다.

## 6. 데이터와 컴포넌트 경계

### 콘텐츠

기존 공통 콘텐츠 모듈의 역사·규칙 원문을 유지하고, 브랜드 프로필과 서버 목록을 분리한다.

서버 데이터는 안정적인 `id`, `slug`, 이름, 서버 유형, `current / planned` 구분, 운영 상태, 한국어·영어 설명, 지원 에디션, 출시 안내, 연결 정보의 공개 여부, 상세 경로를 포함한다. 미확정 정보는 `null` 또는 명시된 미공개 상태로 관리한다.

현재 서버 카드와 Join은 같은 데이터를 사용한다. 접속 CTA는 지원 서버이면서 공개 접속 정보가 확인된 경우에만 직접 접속 행동을 제공한다. 현재 데이터에서는 기존 가이드로 연결한다. 향후 Survival을 공개할 때 서버 데이터 변경으로 카드·상세·Join 상태가 함께 갱신되게 한다.

### 공통 UI

- 브랜드 Hero와 서버 패널은 독립된 컴포넌트로 구성한다.
- 서버 패널은 홈과 `/servers`에서 공유하며 핵심 정보와 CTA를 hover 없이 보여준다.
- Geyser 크로스플레이 장면은 자체 클라이언트 컴포넌트로 격리한다.
- 정보 페이지는 공통 인트로, 작은 브랜드 경로, 링크·버튼 체계와 읽기 폭을 공유한다.
- Reduced-motion 처리는 전체 MotionConfig와 개별 스크롤 장면에서 함께 적용한다.
- 서버 측 뉴스 조회와 metadata는 서버 컴포넌트에 유지하고, 언어 전환·선택·모션만 클라이언트 경계에 둔다.
- 뉴스 summary와 서버 정책 표시는 현재 데이터 구조에 맞춘 작은 순수 함수로 처리한다.

### 보존할 동작

Supabase schema / RLS / RPC / OAuth / Realtime / 문의 번호 / 회원·비회원 권한 / 문의 제한 / 관리자 보고서 발행 / Telegram 알림 계약은 변경하지 않는다. Support와 Taskboard는 시각 체계를 맞추되 기존 제출·조회·대화 핸들러를 보존한다.

## 7. 안내 페이지의 동작

### Join

현재·계획 서버를 먼저 구분한다. 준비 중인 서버는 접속 정보 미공개 상태를 분명히 표시한다. Java / Bedrock은 44px 이상의 탭으로 나누고 기존 접속 방법과 커뮤니티 안내를 유지한다.

공개 주소·포트가 데이터에 추가되면 주소와 포트를 분리한 Copy 컨트롤로 표시한다. 아직 값이 없을 때는 disabled 예시나 임의의 도메인·19132 포트를 렌더링하지 않는다. 기존 1.21.1 안내는 공개된 기존 접속 안내로 식별한다.

### Rules / Recovery

기존 규칙·처벌·복구 정책의 의미는 유지한다. 전쟁 서버의 허용 행위와 예외는 확인되지 않았으므로 새 규칙을 만들지 않고 `기존 공개 규정`과 `전쟁 서버 별도 규정 미공개`를 구분한다. 공통 규칙으로 확정된 목록을 임의로 선정하지 않는다.

모바일은 요약과 펼쳐보기를 사용하되 핵심 제한과 적용 범위는 처음부터 보인다. 서버별 규정이 추가될 때 같은 구조에서 선택할 수 있게 한다. Survival 규칙을 현재 운영 규칙처럼 제공하지 않는다.

### News / Reports / Updates

기존 게시물 URL과 내용을 유지하고 공통 디자인을 적용한다. 모바일 뉴스는 제목·날짜가 겹치지 않는 세로 목록으로 만든다. 기존 홈페이지 업데이트 기록은 홈페이지 기록임을 명확히 해 게임 서버 업데이트와 혼동되지 않게 한다.

보고서 Markdown의 링크, 표, 코드와 긴 제목은 작은 화면에서도 넘치지 않게 처리한다. 게시 날짜를 표시하고 원문에 없는 서버 태그를 만들지 않는다.

### Technology / History

기술 페이지는 그룹의 공통 Geyser 특징과 현재 확인된 ViaProxy 연결 구현을 분리해 설명한다. 아직 준비 중인 서버를 기존 인프라의 실운영 노드로 그리지 않는다.

역사 원문은 유지하고 서버 그룹으로 나아가는 방향은 연도가 확정되지 않은 별도 브랜드 안내로 연결한다. 모바일은 한쪽 세로 타임라인을 사용한다. 이미지의 시대가 확인되지 않으면 특정 역사 항목의 사진으로 연결하지 않는다.

## 8. 화면 크기별 구성과 모션

| 환경 | 구성 | 모션 |
| --- | --- | --- |
| 큰 데스크톱 / 노트북 | 콘텐츠 최대 1400px, 본문 42–68ch, 큰 이미지 창, 두 서버 패널, 주요 nav | 짧은 sticky 구간 안의 transform / opacity 패널 분리 |
| 태블릿 가로 | 서버 2열, 여유 있는 44px 컨트롤, compact nav 필요 시 전환 | sticky를 짧게 하거나 일반 흐름, 작은 reveal |
| 태블릿 세로 | 패널 폭이 좁으면 세로 stack, 적정 최대 폭, compact nav | 짧은 fade / slide, 큰 parallax 없음 |
| 모바일 320–430px | 짧은 Hero, 서버 상태·CTA 우선, 세로 패널, 한 열 본문 | 자연 스크롤, 작고 한 번 실행하는 reveal |

카드가 유효한 읽기 폭을 유지하는 지점과 nav가 겹치기 전을 breakpoint 기준으로 삼는다. `svh`와 안전영역 여백을 사용하고 모바일에서 긴 고정 sticky 구간을 제거한다. resize / orientation 변경 후에는 CSS layout과 Framer Motion의 측정이 재평가되게 한다.

스크롤 가로채기, 필수 콘텐츠의 애니메이션 대기, 지속 루프, WebGL, 커서 추적과 큰 blur를 쓰지 않는다. Reduced motion에서는 연결 구조와 서버 정보가 즉시 완전하게 보인다.

## 9. 접근성, 성능과 metadata

- semantic main / nav / section / heading, skip link, 충분한 대비, 이미지 alt와 버튼·링크 구분을 유지한다.
- 메뉴는 기존 Escape, 포커스 순환·복귀, 스크롤 잠금을 보존하고 safe-area와 화면 내 스크롤을 지원한다.
- 선택 UI는 키보드와 터치로 동작하며 중요한 정보는 hover에 숨기지 않는다.
- 이미지 크기·비율과 페이지 영역을 예약해 layout shift를 줄인다. Hero 이미지의 LCP 우선순위만 높이고 아래 갤러리는 lazy load한다.
- 반응형 `sizes`를 사용하고 큰 PNG 원본을 모바일에 그대로 전송하지 않는다. 원본 보존과 Next 이미지 최적화를 함께 사용한다.
- 새 WebGL / GSAP / 대규모 UI 라이브러리를 추가하지 않는다.
- 기존 공개 경로마다 내용에 맞는 title / description을 설정한다. 기존 게시물은 원문 title과 게시일을 유지한다.
- `.env.local`은 읽기·복사·출력·수정하지 않는다. 로컬 미리보기와 빌드는 환경 파일 없는 별도 복사본과 dummy 공개 설정으로 검증한다.

## 10. 검증과 완료 조건

변경 전 기준은 `npm test` 69개 통과와 lint 종료 코드 0이다. 변경 후에는 기존 기능·보안 검사를 유지하면서 서버 상태에 따른 노출과 접속 동작, 계획 서버 정보 제한을 의미 있는 콘텐츠 테스트로 검증한다. 기존 단일 서버 디자인을 고정한 테스트는 승인된 새 요구사항으로 갱신한다.

검증 화면은 1920×1080, 1440×900, 1366×768, 1280×800, 1024×1366, 1366×1024, 800×1280, 768×1024, 430×932, 390×844, 360×800, 320px 폭이다. 명목상 viewport 설정만 믿지 않고 실제 DOM viewport를 확인한다.

각 크기에서 Header, Hero 제목, CTA, 서버 패널, 이미지, 가로 overflow, 메뉴, Footer, Join 탭, 규칙 펼치기, 긴 한국어를 확인한다. 세로·가로 회전, 메뉴 키보드, reduced-motion, 스크롤 동작도 검증한다.

가능한 검사 표면에서 lint, 타입 검사, 전체 테스트, 환경 파일 없는 production build, 페이지 렌더링을 수행한다. 실제 iOS Safari / Android Chrome / Samsung Internet을 검증할 수 없으면 해당 제한을 명시한다. 운영 문의 제출, 운영 데이터 변경, 외부 발행·배포는 검증을 위해 실행하지 않는다.

완료 시에는 브랜드 위계, 두 서버 상태의 구분, Geyser 기반 크로스플레이 모션, 보존된 URL·정책·역사·지원 기능, 반응형 검증 결과, 미확정 서버 정보가 사실대로 표시되는 것을 확인한다.
